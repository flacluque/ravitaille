# v0.3 : import des activités Strava

Objectif : remplir **les références** (courses et sorties chronométrées qui calibrent le modèle) à partir
de ses activités Strava, au lieu de les recopier à la main.

## Ce qu'on prend dans une activité

| Référence      | Activité Strava (`GET /api/v3/athlete/activities`)                          |
|----------------|------------------------------------------------------------------------------|
| libellé        | `name`                                                                       |
| date           | `start_date_local` (le jour)                                                 |
| distance       | `distance` (m → km)                                                          |
| D+             | `total_elevation_gain`                                                       |
| temps          | `elapsed_time` : **arrêts compris**, comme le veut le modèle (pas `moving_time`) |
| course / entraînement | `workout_type = 1` (« Course » dans le type de sortie) → course ; sinon entraînement, modifiable |

On ne garde que les sports **Course à pied** (`Run`) et **Trail** (`TrailRun`).

## Connexion (OAuth 2)

1. Le coureur crée une « application API » gratuite sur https://www.strava.com/settings/api
   (domaine de rappel : `localhost`) et met l'identifiant et le secret dans `config/application.properties`
   (ignoré par git) ou dans des variables d'environnement. **Le secret reste dans l'API Java**, jamais
   dans le navigateur.
2. « Connecter Strava » → `GET /api/strava/authorize?origin=http://localhost:5173` → page d'autorisation
   de Strava (droit `activity:read_all`, pour inclure les activités privées).
3. Strava renvoie sur `/api/strava/callback` : l'API échange le code contre des jetons, les garde dans
   `~/.trail-planner/strava.json` (lisible par le seul utilisateur) et renvoie vers l'appli.
4. Le jeton d'accès expire toutes les 6 h : l'API le renouvelle seule avec le jeton de rafraîchissement.

Sécurité : un `state` aléatoire à usage unique contre les requêtes forgées ; l'adresse de retour doit être
locale (`localhost` ou `127.0.0.1`).

Limites de Strava : une nouvelle application ne peut connecter que le compte de son créateur, ce qui suffit
pour un usage personnel ; quelques centaines de requêtes par quart d'heure (une page = 200 activités).

## API

| Requête                              | Rôle                                                       |
|--------------------------------------|------------------------------------------------------------|
| `GET /api/strava/status`             | configuré ? connecté ? nom de l'athlète                    |
| `GET /api/strava/authorize?origin=`  | redirection vers Strava                                    |
| `GET /api/strava/callback`           | retour de Strava, puis redirection vers l'appli            |
| `GET /api/strava/activities?after=`  | sorties de course à pied et de trail depuis une date       |
| `DELETE /api/strava/connection`      | révoque l'accès chez Strava et efface les jetons           |

Erreurs : 503 si Strava n'est pas configuré ou injoignable, 401 s'il faut (re)connecter le compte,
429 si la limite de requêtes est atteinte, 502 si Strava répond une erreur.

## Front

- Dans « Tes références », un bouton **Importer depuis Strava** ouvre un panneau :
  - pas configuré : les étapes pour créer l'application ;
  - pas connecté : « Connecter mon compte Strava » ;
  - connecté : la liste des sorties, avec des filtres (depuis telle date, distance minimale, courses
    seulement). Chaque ligne : date, nom, sport, km, D+, temps, et course / entraînement modifiable.
- Les sorties **les plus proches de la course préparée** (en km-effort) sont signalées et peuvent servir
  de tri ; celles déjà dans les références sont marquées.
- Les sorties cochées s'ajoutent aux références ; il reste à cliquer sur « Calculer mon plan ».
